# 0.4.0：协作与承诺

2026-10-26（Asia/Shanghai）。基线 `5069c449`，开发分支 `codex/cooperation-v0.4`。本版实现两个独立规划角色、一个固定规则竞争者和一张有期限的运输工作单。交付源码、本地演示、API/SDK/CLI 与离线评测，默认无模型调用。

## 体验和接口

按 [README](../README.md) 安装并构建，选择「双角色协作」。医生向快递员提出药材需求；快递员按规则接受，自主搜索取材和运输路线，到工坊交给医生；医生实际收到药材后规划制作、运输和最终交付。角色有独立库存、证据、计划、预算与动作实例。

切换「关注角色」可查看各自的认知与计划。工作单面板同时标出权威状态与所选角色收到的状态，消息延迟时两者可以不同。可阻路、移除材料、取消订单、中断当前角色动作，或配置订单期限、消息延迟及商人取材时点。新配置通过「按配置开始新场景」生效。

```bash
.venv/bin/python -m worldmind.cli run --scenario cooperation --output var/cooperation.json
.venv/bin/python -m worldmind.cli replay var/cooperation.json
.venv/bin/python -m worldmind.cli eval --scenario cooperation --output var/cooperation-pair.json
.venv/bin/python scripts/benchmark_v04.py
```

API `POST /api/sessions` 接受 `{"scenario":"cooperation","policy":"Local"}`；省略 scenario 保持原单角色场景。`GET /api/sessions/{sid}/actor?actor_id=doctor` 返回医生投影。协作新增 `order_cancel`（target=`supply-1`）与 `interrupt`（target 为角色 ID）命令，沿用 command_id、expected_revision 和会话凭证。SDK 支持 `CooperationConfig` 或字典，以及 `session.actor("doctor")`。

## 协作协议

新录制版本为 `worldmind-0.4.0/cooperation-1`。单角色继续使用 `worldmind-0.2.1/river-1`；0.1、0.2、0.2.1 的旧动作、规划和执行路径保留。`runtime.py` 显式分派会话、记录与命令，不把协作命令悄悄应用到单角色世界。

### 工作单和观察

本版工作单限定一份药材、一个指定接收者与工坊交接地点，数量全额交付。状态包括 proposed、accepted、in_progress、fulfilled、rejected、withdrawn、cancelled、expired。双方在履行前均可按固定条款撤销；接受后的条款摘要固定。改最终送药目标不隐式改约或撤单。

订单通过有界延迟消息送达参与者。每份消息保存当时的订单快照，旧版本晚到不会覆盖较新状态。角色自己的接受回执，以及双方当面完成的交接可立即形成自身确认；其余变化等待消息送达。接受订单不增加库存、不预留远端材料，也不表示任务一定可完成。

直接观察只覆盖当前区域库存、邻接道路和同地角色。初始简报独立于隐藏世界。ActorContext 不含远端角色状态、全局事件序号、资源预留表、消息队列或世界哈希；全局调试数据不进入规划器。仍采用 TTL 与有限历史值，不提供 v0.5 的自由事实报告、冲突融合或通用证据 DAG。

### 动作、资源与时钟

move、inspect、deliver 在当前步内提交；take、give、craft 的开始和完成跨两个 tick。take 预留现有库存，完成时减场景库存、增自持；give 预留自持药材，完成时原子转移并履约；craft 开始消耗药材，下一 tick 产药，中断不退款。预留不是另一份库存，每角色最多一个活动动作，所有失败和中断释放预留。

每步依次完成到期动作、投递消息、生成角色观察、收集行动意图、仲裁执行，再判定订单到期。用户干预作为独立录制命令在两步之间生效。截止 tick 当步完成的交接计为履约，未完成订单在该步结束时到期；最终目标同样按真实提交判断。租约到期值严格晚于预期完成时刻。消息最早下一 tick 投递。

仲裁先比较相同请求的等待年龄，再使用 tick 决定的轮换顺序；请求内容变化重新计龄，不永久优先同一个角色。固定商人的取材也经过同一执行器。正常转移遵守预留；强制移除材料会中断对应取材，不能留下超额预留。物料账本区分持有、已消耗、已生产、已交付与干预移除，逐命令检查不变量。

模拟采用 barrier，规划 CPU 不消耗模拟 tick。等待有原因、可见状态摘要和最晚结束时间；相同状态不重复搜索，纯时间戳刷新不算新信息。超预算、无材料、到期及取消均有界结束。制作已失败而订单已履约时，医生最多等到最终期限；自主重新下单属于后续扩展。

### Full、Local 与预算

两种策略共享有限动作模型、按耗时排序的搜索、最多 30 动作的计划深度、证据期限及完整计划校验。Local 尝试保留最多两个后缀，局部校验最多占剩余决策额度的四分之一；失败后沿同一个搜索队列继续 Full 搜索。候选全解、窗口拼接与探索前缀都重新校验。预计到货不作为可执行资源前提。

为交接预留两 tick，快递员运输前缀的截止时间为订单期限减二；到场后还需观察接收者是否在场，不能预知其行动。医生先规划到工坊接货，获得实际药材后再规划最终任务。订单接受规则、交接监控与等待策略是确定规则，取材/路线/制作/送达由搜索产生；不声称自由团队任务拆解。

默认决策预算 3,000，每规划角色累计 15,000，场景总计 30,000；节点展开和动作校验计费，失败尝试与回退共用额度。记录每角色与全局指标；CPU 统计规划、验证与探索，不包含全部感知、调度、网络或渲染成本，不等同于原研究规划的总决策 CPU 主指标。

### 回放与资源边界

导出输入和逐步状态/事件哈希，重执行恢复角色认知、订单、待发消息、活动动作、预留、仲裁状态与预算。保存、恢复、游标及续跑共用原存档机制。续跑保持原协议和消耗，源存档不变；协作记录新增父记录摘要及分叉游标，仅是来源元数据，不是签名。

继承单进程、会话锁、取消安全工作线程、16 个活动会话、1,500 条命令回执、2 MB 导入和存档限制。协作记录最多 1,500 条输入，事件接近上限时拒绝继续；固定三角色、一张订单、有限证据和消息使内存工作集有界。终止及中断释放动作预留，服务关闭继续等待已有工作退出。活动会话仍需显式存档才能跨服务重启保留。

## 本轮验证

机器可读结果见 [validation.json](evidence/v0.4/validation.json)，固定案例全部结果见 [comparison.json](evidence/v0.4/comparison.json)。测试结果为本轮实际执行，远程平台状态以 PR Checks 为准。

- 后端 **368 项通过**，语句覆盖 **2,397 / 2,601（92.16%）**，20 条上游测试适配器弃用警告；覆盖新协作、API/SDK、存档、历史记录与资源生命周期，不把语句覆盖当作分支覆盖。
- 前端格式、TypeScript 和生产构建通过；13 项真实服务/Chromium 浏览器检查通过，含双角色认知、订单交接、制作中存档恢复续跑及取消交接。
- 14 组固定场景 × Full/Local = 28 条轨迹均完整重执行一致。全部新录制默认生成至 `var/benchmarks/v0.4`；报告保存完整指标及五份代表性协议回归记录，覆盖正常、竞争、延迟消息、交接取消和短 TTL。
- 原 114 份历史文件未修改，82 种唯一旧录制仍校验全部游标。新增代表记录同样校验每个游标。
- CLI 的协作运行、导出、回放和对照入口通过；原模型协议和配额回归继续离线验证。

## 开发中发现并修正

- 初次版本列表扩充让旧运行时的测试误用协作协议；拆出旧协议列表并增加显式分派，旧运行时不接收新语义。
- 竞争测试最初没有实际制造同一资源冲突：Local 选择保留去药圃的后缀。改用明确的 Full 取材与同 tick 商人请求构造争抢，另保留 Local 的实际行为，不为了通过测试改变策略结果。
- 精确重试应在场景命令转换前返回原回执；调整后，即使导入了另一场景，旧命令的相同重试仍返回原结果。
- 导入记录规范化省略空字段，使续跑父记录摘要与规范导出对应。角色投影及界面快照使用独立值，防止修改返回对象影响权威状态。

## 与后续规划的边界

v0.4 完成两个规划角色、一张全额运输单、确定规则接受/拒绝与条款取消。暂不支持任意订单创建、多订单并行、部分履约、协商改约、自由报告、维修者/修桥或通用动作 DSL。当前协作规划是受限任务与物资语义，未宣称通用多智能体规划器。

原单角色可选模型接口继续保留，协作模型提议入口明确拒绝；没有真实收费调用或供应商联通验证。没有公开部署、Godot 适配、长期生产压力或 10–20 角色容量结论。v0.5 的优先项是证据与承诺依赖、多来源报告和跨角色恢复，研究评测与引擎适配按 [演进规划](plan/08-v0.3之后的功能拓展与演进.md) 继续推进。
