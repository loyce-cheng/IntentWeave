## 修复结果

| 问题 | 修改与关联约束 |
|---|---|
| 三版规划器重复定义预算、BFS、校验器和后缀边界 | 抽到 `planning_core.py`，原模块保留兼容导入；历史 `decide` 独立，旧 Context 字段不增加。动作顺序、预算收费和哈希不变。 |
| 回放逐步创建后立即丢弃界面快照，重复计算哈希 | `advance` 执行并记录，`apply` 继续提供原快照接口。回放使用本次执行产生的轨迹哈希逐步验证，绝不信任导入记录的声明值。 |
| 存档验证之后再次完整重放 | 仓库直接返回已验证引擎，API 安装一次；原 `load` 接口保留。 |
| 暂停、回放、终态也持续轮询，慢请求重叠 | 仅可见且活动的页面串行轮询；隐藏时停止调度，可见时同步一次。读取超时 10 秒，失败退避，连续三次失败或会话失效停止自动刷新。 |
| 角色视图额外请求导致重复传输、跨修订地图 | 使用同一响应中的角色投影，SDK 的 `/actor` 接口保留；旧响应的身份、代次、顺序保护继续生效。 |
| 等待模型时每 250 ms 唤醒，终态启动无效步骤 | 屏障改为事件等待；暂停、删除和模型完成通知唤醒；终态不启动 runner。 |
| 请求取消后线程已提交，但修订号、回执未提交 | `tasks.computation` 等待线程收尾，并在传播取消前运行同步提交回调。命令和模型提议的修订号、回执或审计与实际写入对应。 |
| 删除会话的工作任务可能遗漏于关闭等待 | 注册表保留取消中的任务，完成后删除引用；关闭服务统一等待，测试检查会话可被垃圾回收。 |
| 幂等回执长期持有完整嵌套对象图 | 保存压缩 JSON，读取时返回独立副本；保留最多 1,500 条原响应和原指纹，不通过丢弃旧回执破坏幂等性。 |
| SQLite 同步等待阻塞事件循环；缓存命中仍写盘并续期 | 额度、缓存和审计使用取消安全的工作线程；连接在 finally 关闭。额度预留途中取消仍收尾审计；缓存命中不重写。 |
| CLI 先读完整文件再检查大小 | 仅读取上限加一个字节后判断；SDK 凭证校验统一由对象构造负责。 |
| 显式空干预表被默认场景替换 | `compare(commands=[])` 保持无干预，只有 `None` 使用默认断桥。评测脚本不再生成无用快照，旧评测入口增加 main guard。 |

公共依赖保持从 `domain` → `planning_core` → 版本策略 → `engine` → 会话/存档/API 的方向；`tasks` 不反向导入 API，模型网关与 API 共用取消处理。没有用无界全局缓存替代重复代码，也没有共享可变动作实例。

## 开销对照

同一环境：Linux x86_64、Python 3.12.14。脚本分别导入基线和审查后的源码。

| 固定测量 | 基线 | 审查后 | 变化 |
|---|---:|---:|---:|
| 64 份录制完整回放，5 次进程 CPU 中位数 | 1,268.36 ms | 476.90 ms | 降低 62.4% |
| 第 8 tick 快照的 1,000 条幂等回执，GC 后 Python 保留分配 | 17,234,524 B | 1,638,478 B | 降低 90.5% |
| 同一回执测量的 Python 分配峰值 | 17,500,388 B | 2,668,878 B | 降低 84.7% |

回放计时包含引擎执行及哈希，不是纯规划预算或 HTTP 吞吐；回执测量是固定快照压力案例，`tracemalloc` 不等于进程 RSS。技术重复会受环境负载影响，原始样本已保存，不能据此承诺任意场景的相同收益。

## 保留的边界

会话数、命令回执、录制步骤、事件、搜索预算、模型并发和持久数据仍有明确上限。闲置会话沿用请求/创建时检查过期的机制，数量最多 16 个，没有增加周期清理线程。SQLite 最长锁等待仍是 5 秒；取消需等待已开始的工作收尾，以保证一致性，因此不是立即中断底层线程。

这轮验证证明了列出的生命周期路径和历史样本兼容；未做长期生产负载或跨进程共享状态测试。单进程服务、有限动作模型，以及短 TTL 无解案例的搜索成本边界仍见 [实现协议](IMPLEMENTATION.md) 与 [0.2.1 报告](TEST_REPORT_V021.md)。
