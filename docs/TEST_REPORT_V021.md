# Worldmind 0.2.1 改进与验证报告

2026-10-23（Asia/Shanghai）。基于 0.2 最新提交 `dc89e42`，工作分支 `codex/improve-v0.2`。
[机器可读验证](evidence/v0.2.1/validation.json)、[全部对照数据](evidence/v0.2.1/comparison.json)。
历史 [0.2 报告](TEST_REPORT_V02.md) 和原始记录保持不变。

## 已完成的改进

- Local 在一次 BFS 中探测多个后缀，失败后继续同一队列做 Full 搜索，不重复展开已有状态。两种策略共用必要可达性检查、动作模型、预算和未知处理；边界分析与失败校验仍计费。
- 证据将到期时保留已认证前缀，在消费失效事实之前检查。观察路线优先当前目标和已知材料来源；历史观察只排序探索方向，不续期、不充当执行前提。重复观察且认知/资源没有进展时以 `unknown` 结束当前尝试。
- 新增 `POST /api/sessions/{sid}/resume`、`session.resume()` 和“从此处继续”。从已验证游标继续执行，保持原预算、制药状态、商人状态、证据、观察记忆和版本。源存档不变，新分支可再次导出并完整校验。
- 续跑支持 revision 冲突检查与幂等回执，提升会话 epoch 后迟到模型提议失效；不会自动运行或发起模型调用。
- 新协议 `worldmind-0.2.1/river-1`；冻结 0.2 规划器，旧协议继续按原算法重执行和续跑，不能通过改版本标签迁移。

## 关键对照

预算单位为节点展开加动作校验，包含后缀分析；0.2.1 的必要地图遍历也计为展开。
普通送药仍是两策略各 86 单位、9 tick。两版均使用相同固定输入。

16 场景 × 2 协议 × 2 策略生成 64 份完整回放，全部重执行一致；没有过滤失败。
每项做 5 次技术计时重复，结果哈希一致。额外固定枚举 3 目标 × 4 干预时点 × 10 种干预 = 120 组 Full/Local 对照，Local 预算超额 0 组、状态不一致 0 组。

这解决了原缺材/双路失效样例中 Local 的额外预算开销，不保证任意输入或紧预算下 Local 都不劣于 Full。CPU 计时包含规划、Context 构建、检查和观察循环记忆处理，不包括观察合并、动作执行、HTTP、渲染或 IO；预算单位也不等价于 CPU 时间。少数案例的 Local CPU 中位数仍高于 Full；5 次技术重复不是独立样本，不能据此宣称普遍速度优势。

## 过程中发现并修正

- 第一轮仅改观察方向仍使 TTL=2 与断桥/竞争组合循环；增加历史观察偏好，仍坚持真实认知认证，并加回归。
- 扩展不可解短 TTL 场景暴露重复探测；增加确定性的无信息进展终止，保留其较高搜索开销。
- 新协议初次遗漏 Recording 的允许值，补全协议分派后验证所有历史记录；未修改旧哈希。
- 制药续跑测试最初保存可变指标引用，后续执行污染了预期快照；改为深拷贝，保留严格相等断言。
- 默认无网络沙箱阻塞了 HTTP 测试事件循环；终止该次未完成运行，授予本机网络能力后完整重跑。npm 缓存目录不可写，改用 `/tmp` 缓存；安装没有绕过完整性校验。

## 使用与限制

恢复存档或导入 JSON → 可选回放游标 → “从此处继续” → 单步或运行。
SDK 对应 `restore_archive(receipt)` / `import_recording(data)` → `seek(n)` → `resume()`。
续跑不会补充预算、解除终态或改写历史协议；旧 0.2 记录续跑仍使用旧算法，重置才开始新的 0.2.1 模拟。

当前仍为有限地图、单规划角色、单进程演示。没有独立研究基准、真实供应商调用、公开部署或长期压力测试。原存档期限/凭证机制不变；未保存的活动会话仍会在服务重启后丢失。
