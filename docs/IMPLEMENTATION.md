# v0.2.1 实现协议与已知限制

应用版本 `0.2.1`，新记录协议为 `worldmind-0.2.1/river-1`。
本版基于 0.1 重建实现，按 07 计划推进恢复边界、持久回放和 SDK。
原 0.1 / 0.2 记录协议继续受显式兼容分派支持；没有恢复此前遗失的云端实现。

## 世界、动作与角色

七区域、八条双向道路，静态地图和地点用途是公共信息。动态通行状态和库存只在当前区域直接观察，或来自初始带时效的配送简报。初始简报是独立常量，不由世界真相复制；隐藏干预不会改变它。

快递员为唯一规划角色；医生固定在诊所接收交付；商人固定在仓库，默认等待，可用 `Config(merchant_takes_at=2)` 在指定 tick 按规则取一份药材。患者住处是交付目标。商人不调用模型，也不自主规划。三预设目标为患者药物、诊所药材、诊所药物；每个目标完成一次即满足。

| 动作 | 条件 | 提交效果 / 取消 |
|---|---|---|
| move | 邻接道路在执行时真实可通行 | 一个离散步后到相邻区域，不瞬移 |
| inspect | 目标是当前区域 | 刷新当前库存及邻接道路的直接观察；规划验证止于观察屏障 |
| take | 当前区域有药材、自身药材少于 2 | 原子减库存、增自持药材 |
| craft | 工坊有一份自持药材、药物少于 2 | 第一 tick 消耗药材，下一 tick 产药；中断无退款 |
| deliver | 在当前目标接收地点，持有所需物品 | 原子消耗/转移并登记该目标交付 |
| wait | self 或当前地点 | 一 tick，无资源变化；搜索器不生成无收益等待环 |

单步先推进 tick、处理固定背景取材、完成上一步制作，再刷新观察、规划和执行一个动作。
制作完成的 tick 不再开始另一动作。除 craft 外的动作在一个离散步内原子提交；这比长期文档中通用 start/continuous/finish/租约系统更窄，原因是保持首版六动作语义可检验。
没有跨 NPC 工作单、通用 escrow、任意长动作、任意资源或通用游戏引擎。

## 信息边界与规划

规划器只接收独立的 `Context(State, goal, evidence expiry, actor versions)` 值对象；该 State 由自身确认状态和角色证据构造。它不包含真实远端库存、商人状态、全局日志序号、世界哈希或调试权限。模型只收到角色上下文、公共地图和静态动作语义。页面世界面板为特权调试；角色地图使用当前响应内已有的 `actor.context.state` 投影，保持同一修订号；独立 `/actor` 接口仍保留给 SDK。

过期证据变成 None/未知，不自动反转真假。没有概率信念、传闻合并、冲突多来源推理；证据历史可通过输入重执行获得，不存完整通用信念数据库。隐藏变更命令立即改变世界，角色在下一次合法观察阶段才能得知。

Full/Local 共享 BFS、状态编码、30 动作深度边界、未知处理和 `transition` 校验器。
预算单位明确为“一个节点展开”或“一次动作校验/后缀动作分析”；这些操作都占同一个每次/累计预算。
Local 尝试替换未执行计划的连续前窗口 `[0,r)`，保留后缀。0.2.1 对最多两个非空后缀编译必要入口条件，然后在一个 BFS 队列中同时检查后缀拼接和完整解。局部检查额度到期后，继续同一队列完成 Full 搜索；不会因扩大窗口或回退重新展开相同状态。边界分析和失败校验仍计入共享预算；拼接后最多 30 个动作，所有证据期限和资源条件必须通过完整验证。

两种策略都先做基于已知道路、材料和目标的必要可达性检查；实际遍历的地图节点计入展开预算。固定静态地图所有边已知可通行时无需遍历。该检查只排除当前认知内无法构造的方案，未知信息仍可触发观察；不使用隐藏世界判断无解。

证据到消费时过期时，保留已认证前缀并在使用失效事实之前设置检查点。选择观察方向时优先已知材料来源，其次角色记忆中的来源，优先避开以前观察到的断路。假设路线仅用于选择观察点，必须再用未修改的真实认知校验，只安装第一个未知/过期条件前的前缀和 inspect。`last_values` 不刷新 TTL，不把过期事实升级为可执行前提；找不到其他路线时仍可重新检查以前失败的来源/道路。

短 TTL 下完全缺材或无路可达可能造成重复观察。运行时对“角色认知、已观察值、目标和待观察路线”的组合保留确定性摘要；重复同一观察尝试且没有信息/资源进展时，以 `unknown/observation_cycle_without_progress` 结束当前尝试。时间戳更新本身不算信息进展。该记忆属于角色可见状态，进入回放哈希和存档续跑；不依据商人隐藏状态或世界日志。它是停止当前无进展尝试的策略，不是永久无解证明。

固定案例与额外扰动结果见 [0.2.1 报告](TEST_REPORT_V021.md)，历史 0.2 负面结果保留在 [原报告](TEST_REPORT_V02.md)。算法仍基于有限六动作模型，没有声称最优修复、通用 DAG 或普遍成本优势。

未知事实需要先到达观察点，返回 inspect 结尾的可执行前缀；不虚构 inspect 结果再认证后续计划。
无搜索结果返回 `unknown/no_plan_in_current_belief`，预算耗尽返回 `budget_exhausted`；没有使用评测器全知状态提前报告永久无解。

界面 CPU 数值只测规划与序列验证过程，不含观察合并、HTTP、渲染、模型网络等待，不能直接代替长期研究协议的总决策成本指标。所有正式研究统计、独立场景、性能规模标定均未完成。

## 并发、取消与会话

FastAPI 单进程，`sessions.py` 管理会话凭证、创建限额和生命周期；HTTP 路由负责协议转换，存档仓库负责持久化。每会话 asyncio lock 单写者；有界计算在工作线程执行，即使请求被反复取消，也保持 shield 等待工作线程完成后才传播取消并释放写锁。成功写入的修订号与幂等回执在取消传播前一并提交。后台正常执行每 250 ms 推进一步；模型屏障期间等待事件，暂停、模型完成或删除会话立即唤醒，终态不再自动推进。四个计算槽限制并行核心任务。删除会话后仍在取消中的任务保留到完成，关闭服务也会等待这些任务退出。

`/commands` 必须提供会话 token、command_id、expected_revision。同 ID 同内容返回原响应的新副本；回执使用压缩 JSON，最多 1,500 条，避免持有完整嵌套快照。同 ID 异内容拒绝；两个相同 revision 的并发写入只允许一个成功。revision 是调试会话控制字段，不进角色上下文。控制操作（run/pause/reset）不是世界动作，但均推进会话 revision，避免运行状态变化与旧响应混淆；界面不自动重试它们。

前端将 HTTP 请求、响应接受规则和存档凭证存储拆为独立模块。轮询及模型响应使用会话身份、交互代次和响应顺序检查；旧会话或旧操作的响应不能覆盖当前界面。只有运行中或模型等待中的可见页面会串行轮询，单次读取最多等待 10 秒；失败退避，连续三次失败或会话失效停止自动请求。暂停、回放、完成和隐藏页面不定时刷新，重新可见时同步一次。页面刷新会建立新活动会话，不自动续接旧模拟。

模型请求处于 barrier，暂停模拟等待回复；干预、目标修改、取消、重置仍可进行。会话 epoch 与角色上下文摘要共同防止旧回复覆盖。隐藏世界变化本身不让提议过期，避免该行为成为信息旁路；最终动作仍按真相复核。SQLite 额度、缓存和审计操作在工作线程执行，连接在退出时关闭；取消等待已开始的数据库操作收尾，已提交的额度预留仍记为取消且不退款。缓存命中只读取和校验，不刷新创建时间或再次写入缓存。取消不能保证供应商停止计费，因此请求额度不退还。

会话 token 为不可预测的能力凭证，不在 URL 中；这是演示服务的隔离机制，不是完整用户账号体系。
模型入口还需独立服务端口令。设置 Host 与 Origin 限制；无任意浏览器端 URL/密钥配置。
当前没有完善的多租户身份管理、分布式限流、TLS 终端或生产可用性保证。

## 回放与持久化

导出含版本、初始配置、每条输入、每步逻辑状态哈希和事件哈希。导入先全部重执行验证，成功后才替换会话；回放每步仍重新校验。`advance` 执行并计算轨迹哈希，`apply` 在此基础上生成独立界面快照；回放、批处理及后台步骤使用 `advance`，不创建将被丢弃的视图，也不重复计算同一步哈希。CPU 时间等非确定字段不入哈希。模型通过校验后的动作提议作为结构化输入记录；重放不调用模型。

模型审计独立持久保存，网络错误、取消与用量不作为世界剧情真相。导出不含 API Key、认证头、任意原始响应或隐藏思考。回放能重建世界和动作/规划轨迹，**不重现真实网络时延、模型等待动画或供应商计费过程**。

哈希用于发现损坏和不一致，不是数字签名；能重写整个记录并重算哈希的操作者可构造另一条合法轨迹。

`version.py` 区分应用版本和录制协议。0.1 / 0.2 记录分派到 `compat/planner_v01.py` / `compat/planner_v02.py` 的历史决策策略，0.2.1 使用当前规划器。三个策略仅将等价的预算、BFS、校验和后缀边界抽到 `planning_core.py`；旧 Context 仍只有原六个字段，当前 Context 继承后增加观察记忆。96 份已有录制文件（原 0.1、原 0.2 及 0.2.1 对照目录）及所有游标作为兼容回归。没有改写旧记录的版本或重算旧哈希冒充迁移；未知协议拒绝。三个版本共享仍未变化的有限动作语义，未来改变动作或执行顺序时，必须增加相应协议实现和回归证据。

`archives.py` 将显式保存的回放存入独立 SQLite 文件，默认 `var/replay-archives.sqlite3`。每个存档有随机 ID 和独立高熵访问凭证；服务端只保存凭证 SHA256，没有公共列表、凭证找回或账号系统。创建和读取都校验结构、摘要与完整回放；恢复保留这次验证生成的引擎再替换当前会话，不二次重放。保存处于回放中间游标的会话时，保存完整原始录制。恢复默认进入只读状态，不启动模拟或模型调用。`POST /resume` 在会话写锁内校验 command_id / expected_revision，将已验证游标转为暂停的可执行分支，清除回放标记并提升 epoch，拒绝旧模型回复。保持 Engine 的原协议、轨迹前缀、执行中动作、消耗预算、观察记忆和证据时间。源存档不变；新轨迹可另行导出、校验和保存。续跑不解除终态，不自动再次调用模型；重置才会开启当前协议的新模拟。

默认存档 7 天到期，最多 64 份、64 MiB 有效载荷、每份 2,000,000 字节。事务同时检查数量和实际 payload 字节数，不能通过并发写入超占；创建时删除过期行。配额不含 SQLite 索引、日志及空闲页。损坏记录、存储故障和错误凭证有明确错误码，不向客户端回显数据库路径或原始内容。

浏览器本地索引包含存档凭证，保存在当前站点 localStorage。清除站点数据会丢失这些句柄，服务不会按姓名或其他身份找回；导出的普通回放 JSON 不含凭证，可用于跨设备传递。服务端数据库和本地索引都未加密，不能抵御恶意数据库管理员或同源脚本泄露。

活动模拟会话仍在内存中，重启后丢失；显式存档、模型额度账本分别持久化。持久性以磁盘实际保留和备份为前提，临时托管文件系统不能保证重启保存。

## SDK 边界

`worldmind.sdk` 提供同步 HTTP 客户端、会话句柄、存档回执和 `SDKError`。默认请求超时为 10 秒，配置范围为 `(0,60]` 秒，沿用 httpx 的连接/读写超时语义。SDK 不自动重试、不跟随重定向，使用默认代理和 CA 环境设置。外部注入的客户端由调用者关闭，内部创建的客户端由 context manager 关闭。

命令未给 revision 时先读取当前状态，再提交一次；并发修改仍可能返回 409，不自动覆盖。显式重试必须保留原 command_id 与 expected_revision。模型调用没有 SDK 便捷入口。凭证在句柄 repr 和错误信息中隐藏，但持有对象的调用者仍能访问它，仍须妥善保存。完整接口见 [SDK 指南](SDK.md)。
