# Worldmind 0.2 升级计划与进度

基线：`e65287d4a4df65f25b14aed592f1928ccb65168f`，0.1 PR #1 尚未合并 main。
独立远程分支：`codex/upgrade-v0.2`；本轮沿用已授权的阶段提交、推送、哈希核对及 PR 流程。

## 本轮范围

按 07 计划的 v0.2 顺序，聚焦恢复边界、持久回放和 SDK，不进入多自主角色、公开部署或付费模型。

1. 优化 Local 对候选后缀的重复校验；保持全计划认证、认知隔离与相同预算，保留不利结果。
2. 增加有容量/时效/凭据控制的 SQLite 回放存档，服务重启后仍可导入逐步验证；不自动恢复后台运行。
3. 版本升级至 0.2.0；明确记录协议分派，以冻结的 0.1 规划器验证原有 14 份回归记录，不改写旧哈希冒充迁移。
4. 整理会话边界与 Python 客户端接口，前端提供存档保存/恢复/删除，修正并发旧响应覆盖风险。
5. 后端与协议异常回归、浏览器实际操作、类型与构建、可重复前后对照；更新说明和版本报告。

## 验收与保存

- 原 0.1 记录均能按原协议重执行，0.2 记录损坏/未知版本拒绝。
- 存档跨实例重启、错误凭据、过期、限额、损坏、并发写入均有明确结果；不存供应商密钥。
- Full/Local 成本使用实际展开+校验计数，分别记录 0.1 与 0.2；不把少数案例宣称成统计结论。
- SDK 与 UI 通过实际服务验证；真实供应商仍未调用。
- 每个可检查阶段提交推送并核对远程 SHA；最终创建增量 PR，以 0.1 开发分支为基础。
